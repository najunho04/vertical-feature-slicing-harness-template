# 작업 규칙

## 경계
- 다음 경로는 읽기 전용이다. **수정이나 추가가 필요하면 코드를 작성하지 말고 멈춰라**. 이후 필요한 변경 사항을 사용자에게 설명해라.
  - `backend/src/common/**`, `backend/src/shared/**`
  - `front/src/common/**`, `front/src/shared/**`
- 다음 경로는 절대 수정하지 말 것. 통과하지 않으면 구현한 코드를 고치고, 명세와 불일치하면 멈추고 보고하라.
  - `backend/test/contract/**`, `front/test/contract/**`, `e2e/**`
- 설정 파일(`CLAUDE.md`, `package.json`, `.eslintrc`, `.claudeignore`, `.husky/**`)은 절대 수정하지 말 것.
- `--no-verify`, `HARNESS_APPROVED=1` 등 커밋 훅을 우회하는 행위를 하지 말 것. `HARNESS_APPROVED`는 사용자만 쓴다.
- 배정된 슬라이스 폴더 밖의 파일은 수정하지 말 것.
- 다른 `feature/` 하위 폴더를 import하지 않는다. 의존 가능한 것은 `common/`과 `shared/`뿐이다.
- 새 의존성 추가, 스키마·마이그레이션 변경은 단독으로 하지 말고 먼저 제안하라.
- **사용자의 명시적 허용이 있기 전에는 무조건 경계 사항을 지켜야 한다.**

## 타입
- 엔티티·DTO·enum은 `common/`에서 import해 쓴다. 재정의 금지.
- 프론트 타입은 백엔드 DTO와 반드시 일치시킨다.
- 상태값·역할·에러코드는 문자열이 아니라 enum을 쓴다.
- 엔티티를 응답으로 직접 내보내지 않는다. 반드시 DTO를 거친다.

## 구현
- **절대 임의로 구현하지 않는다. 파일, 코드, 컨텍스트카드 등 명시적 내용을 따르고, 중의적이거나 모호한 표현은 사용자에게 재질문 할 것.**
- **기존 슬라이스 구조를 따른다.**
- 인증·예외·응답 등 공통 동작은 직접 만들지 말고 `shared/`의 것을 쓴다.
- **변수·함수명은 축약하지 않는다. 풀네임으로 쓴다.**
- **타입 오류를 `any`나 무시 주석으로 덮지 않는다. 막히면 보고하라.**
- 테스트를 skip하거나 주석 처리하지 않는다. 통과하지 않는 테스트를 삭제하지 않는다.
- `test/unit/{slice}/**`은 TDD 형식으로 작성·수정한다. 다른 슬라이스의 단위 테스트 폴더는 건드리지 않는다.

## 실행
- 서버 기동: `npm run dev` (다른 방법으로 띄우지 말 것)
- 단위·계약 테스트: `npm run test`
- E2E: `npm run test:e2e` (슬라이스 완료 시에만)

## 기타
- 사용자가 루프를 언급할 때에는 명시적 스탑 평가 기준이 있는지 확인한다. 없다면 스탑 기준을 재질문한다.
- 2번 이상 나온 실수는 사용자에게 직접적으로 실수 원인과 실수 내용을 언급한다.
- **모든 내용은 직관적이고 간략히 제공한다.** 사용자의 추가 설명 요청에 한해 길게 구체적으로 제공한다.
