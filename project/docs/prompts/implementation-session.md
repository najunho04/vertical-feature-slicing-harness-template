# 구현 세션 프롬프트

피쳐별 세션. 테스트 세션과는 **다른 새 세션**으로 연다. 계약 테스트가 커밋(동결)된 뒤에만 시작한다.

슬라이스마다 이 템플릿에 카드를 붙여 `project-all-docs/prompts/{slice}-implementation-session.md`로 저장해 두고, 세션에는 그 내용을 붙여넣는다.

```
아래 슬라이스를 구현해줘.

- backend/test/contract/{slice}/ 의 테스트를 통과시키되, 그 파일은 수정 금지.
- 공용 레이어(`common/`, `shared/`)는 읽기 전용. 변경 필요하면 멈추고 보고.
- 세부 단위 테스트는 TDD로 먼저 작성. 위치: backend/test/unit/{slice}/, front/test/unit/{slice}/
- 레퍼런스 구조: backend/src/feature/{레퍼런스 슬라이스}/, front/src/feature/{레퍼런스 슬라이스}/ — 폴더 구조·파일 이름·역할을 그대로 따를 것.
  - 다른 슬라이스의 코드를 import 하지 말 것. 공용으로 옮겨야 한다고 판단되면 멈추고 보고.
- 완료 기준: `SLICE={slice} make test-slice` 통과 (계약 + 단위), `make lint` 통과. 커밋은 하지 말고 결과를 보고할 것.

[컨텍스트 카드]
```

첫 슬라이스(레퍼런스)일 때는 레퍼런스 구조 줄 대신 아래를 넣는다.

```
- 이 슬라이스가 첫 레퍼런스 슬라이스다. 이후 모든 슬라이스가 이 폴더 구조를 그대로 따라 하게 된다.
  - 코드를 쓰기 전에 백엔드·프론트 폴더 구조(파일 이름과 역할)를 먼저 제안하고 멈춰서 승인을 기다릴 것.
  - 단순하고 반복 가능한 구조로 할 것. 이 슬라이스에만 필요한 추상화는 넣지 말 것.
```
